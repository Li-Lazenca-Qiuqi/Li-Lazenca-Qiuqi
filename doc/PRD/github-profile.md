# GitHub 个人主页产品需求

状态：草案，待确认。日期：2026-09-12。项目：Li-Lazenca-Qiuqi。

## 1. 背景与目标

用户以朋友的 GitHub 主页为参考，希望了解并形成自己的主页方案。本方案基于该聊天，规划一个体现气象科研与软件开发身份的 GitHub Profile README，通过清晰介绍、统一视觉素材与贡献展示提升辨识度。

当前授权交付包含项目记忆、本 PRD 与本地 Demo；Demo 已完成，参见[预览说明](../note/demo-preview.md)。聊天中 Banner、徽章、统计卡片与贪吃蛇均来自助手建议，本文将其组织为拟实施需求，不代表用户已逐项确认。

需求来源与核验边界见[来源笔记](../note/chat-source.md)，技术路线见[选型记录](../decisions/001-profile-readme.md)。

## 2. 受众与使用场景

- 科研同行：快速识别研究领域与计算能力。
- 开发者与潜在协作者：了解常用语言、工具和公开技术定位。
- 主页维护者：通过少量文本与资源调整保持内容准确，减少日常手动更新。

成功标准：访客可从文字直接理解个人定位；视觉元素风格一致；GitHub 深浅主题和窄屏下内容可读；动态模块失败不阻断介绍。

## 3. 范围与优先级

P0 为静态主页核心，P1 为聊天提出的视觉和动态增强。优先级是本草案的实施建议。

| 编号 | 优先级 | 功能 | 可交付行为 |
| --- | --- | --- | --- |
| FR01 | P0 | 个人介绍 | 展示确认后的昵称、定位与简短介绍，文字不依赖图片 |
| FR02 | P0 | 研究与技术分类 | 分为 Atmospheric Science、Computing、Agent Stack、Developer Tools；仅展示确认内容 |
| FR03 | P0 | 气象 Banner | 提供统一气象主题 SVG；可采用云层、等压线或风场意象，文案使用英语 |
| FR04 | P0 | 统一徽章 | 统一高度、间距与样式，提供可读名称和替代文字 |
| FR05 | P1 | GitHub Stats | 根据确认的账号显示统计卡片；不展示虚构数据，不强制自建服务 |
| FR06 | P1 | Contribution Snake | 生成深浅两套贡献动画，支持手动运行及拟每日更新，引用最近有效产物 |

不在本期范围：独立网站、React/FastAPI 应用、数据库、访客跟踪、博客、论文数据库、自动读取私有活动、自建统计服务平台。教育经历、联系方式、精选项目不是聊天已确定的栏目，不默认填充。

## 4. 信息架构与内容规则

建议顺序：Banner → 个人介绍 → Atmospheric Science → Computing → Agent Stack → Developer Tools → GitHub Stats → Contribution Snake。

- 文档与普通介绍优先使用简体中文，专业术语及 SVG 中的文字使用英语；最终主页语言组合见 Q02。
- 个人定位可采用 Atmospheric Scientist & Developer；属于拟定公开文案。
- Python、C++、Fortran、uv 等可作为候选工具；科研模式及 AI 产品名称需按真实使用情况筛选。
- 不从工具偏好推断工作单位、学位、成果或熟练度。
- 无内容的分类可合并或隐藏，避免为填满布局而添加信息。
- 每个图片提供含义明确的替代文字；核心介绍与技术名称应有文本表达。
- 图片和徽章目标地址使用确认后的账号，不残留朋友用户名或示例用户名。

## 5. 视觉与交互要求

- 以气象科研为主视觉，保持标题层级、留白和徽章规格一致。
- 深浅主题均保持文字和背景可区分；核心 Banner 优先保证静态可读，动画为可选增强。
- 图片宽度适应可用区域，不依赖固定的大屏宽度。
- 不使用闪烁效果；若采用持续动画，同时提供可访问的静态版本。
- 允许点击徽章前往明确的官方工具页面，但不得使用无意义的占位链接。
- 不要求 README 中运行 JavaScript 或自定义页面交互。

## 6. 更新与故障处理

- 介绍、徽章及 Banner 通过仓库资源维护；本期不要求管理后台。
- Stats 的服务来源、缓存与失败替代方案在实施前选定；第三方服务不可用时，不影响静态主体。
- Snake 拟用 GitHub Actions，支持手动触发与每日调度；不承诺调度准点完成。
- 动画生成成功后才更新展示产物；失败时保留最近一次有效版本，通过 Actions 运行状态查看问题。
- 首次产物生成前使用静态占位图或暂不展示该模块，避免发布断链。
- 凭据仅经适用的 GitHub 机制传入工作流，不写入资源或公开链接。

## 7. 验收条件

| 编号 | 对应需求 | 验收方法与通过条件 |
| --- | --- | --- |
| AC01 | FR01–FR02 | 对照确认后的资料逐项检查，姓名、研究方向、工具与链接无虚构、无待填占位符 |
| AC02 | FR01–FR04 | 在 GitHub 实际渲染页面检查结构，标题有层级、图片完整、替代文字齐全 |
| AC03 | FR03–FR06 | 分别检查 GitHub 深色和浅色主题，文字可读，主题资源匹配 |
| AC04 | FR01–FR04 | 在约 375 px 窄屏与约 1280 px 桌面宽度检查，无模块遮挡或页面横向溢出 |
| AC05 | FR05 | 对照确认账号和数据来源核对卡片，模拟卡片失效后仍可阅读介绍与技术内容 |
| AC06 | FR06 | 至少一次手动运行成功并产生两套有效 SVG；检查调度配置，并验证失败不会覆盖最近有效产物 |
| AC07 | 全部 | 发布后确认公开同名仓库根 README 显示在目标个人主页；检查所有图片及链接，记录实际验收结果 |

现已完成本地 Demo 与桌面/窄屏、主题、资源和控件检查；上述 GitHub 正式产品验收尚未执行。无运行环境或远程仓库时，不能把本地文本检查等同于 GitHub 展示通过。
