# 文档维护约定

- PRODUCT.md 记录产品定位、现有功能、关键流程、支持范围和已知限制；区分已实现能力与计划需求。
- TODO.md 是唯一活动待办清单；定期将已完成事项归档，保留原编号、日期与回溯链接。
- Roadmap.md 记录阶段目标，不复制日常工作流水账。
- PRD/ 保存需求和验收条件；同一主题优先更新现有文档。
- decisions/ 保存长期有效的选型及理由，明确提议和已采用状态。
- note/ 保存专题说明、来源依据和带日期的核验结果；运行中的服务等短期状态不得写成永久事实。
- archive/ 保存可追溯的历史记录，按需读取；归档后更新活动文档链接，不维护第二份活动待办。
- 根 AGENTS.md 保留稳定背景、技术栈和索引，易变产品状态统一在 PRODUCT.md 维护。
- 根目录 README.md 是 GitHub Profile 交付物，`site/` 是独立个人网站；两者的维护说明在本目录，不将内部记忆写入公开页面。
- 更新事实时同步直接相关的文档，避免将 Demo、本地检查或文件创建等同于正式 GitHub 验收。
